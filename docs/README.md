## 0. สำหรับ AI / โมเดลเล็ก — เริ่มอย่างไร (ไม่ต้องถามผู้ใช้ว่า "จะให้ทำอะไร")

คำตอบคือ **ทั้งสองอย่างรวมกัน ไม่ใช่เลือกอย่างใดอย่างหนึ่ง:**
- **Roadmap บอกว่า "ทำอะไรต่อ"** = รายการงาน `W…` ใน `06 §5` และสถานะใน `PROGRESS.md`
- **ไฟล์กฎกำกับ "ทำอย่างไร"** = `AI_WEB_RULES_10B.md` (ทางเข้า: `AGENTS.md` ที่ราก repo ซึ่งชี้มาที่ไฟล์นี้)

ขั้นตอน (ทำตามนี้ ห้ามอ่านทุกไฟล์ใน `docs/` — เอกสารรวมยาวเกิน context ของโมเดลเล็ก):
1. อ่าน `AGENTS.md` (ที่ราก repo) แล้วอ่านกฎเต็ม `AI_WEB_RULES_10B.md`
2. เปิด `PROGRESS.md` → เลือก **งานแรกที่ `todo` ซึ่ง "ต้องมีก่อน" เป็น `done` ครบ** → ตั้งเป็น `doing`
3. อ่าน **เฉพาะ** ส่วนที่งานนั้นต้องใช้: แถวของงานใน `06 §5` · FR ที่แถวนั้นระบุ (`03 §2`) · หัวข้อหน้าที่เกี่ยวข้อง (`05 §3/§4/§5`) · ฟิลด์ contract ที่ใช้ (`02 §2`) · ตัวอย่างที่ต้องลอก (`docs/examples/` หรือไฟล์ที่ทำเสร็จแล้ว)
4. (Brief ของงานอยู่ที่ `docs/tasks/<ID>.md` — มีให้แล้ว W0a–W0c) เขียนแผน 3–7 ข้อ → ลงมือ → รัน `check` → รายงานตาม `AI_WEB_RULES_10B §10` → รอคน review → คนเปลี่ยนเป็น `done`
5. **ถามผู้ใช้เฉพาะเมื่อ:** (ก) ขาด Prerequisite D1 (`06 §3`) (ข) Brief/กฎคลุมเครือ — ถามแบบเลือก A/B ไม่เกิน 3 ข้อ (ค) ต้องแตะไฟล์นอกขอบเขต/`frontend/contract/**` (ง) ติด 3 ครั้ง (`06 §9`) (จ) งานขัดกับกฎ — บอกว่าขัดข้อไหน

ถ้าผู้ใช้พิมพ์สั้นๆ เช่น "เริ่ม" หรือ "ทำต่อ" → ให้ถือว่าหมายถึงขั้นตอน 1–4 ข้างบน

## 4. คำศัพท์ที่ใช้ตรงกันทั้งชุด

| คำ | ความหมาย |
|---|---|
| Problem / Schedule / Report | ข้อมูลโจทย์มาตรฐาน / ผลตาราง (มี assignments + Lunch) / รายงานการตรวจ (02 §2) |
| Session | หน่วยที่ solver จัด = (วิชา × กลุ่มที่เรียนพร้อมกัน) (04 §4.1) |
| Job | งานจัดตารางแบบ async: `queued → running → done / failed / cancelled` · เมื่อ `done` มี outcome `solved / partial / infeasible` (02 §2.3) |
| stub / http | โหมด api-client: อ่านข้อมูลตัวอย่าง / เรียก algorithm จริง |
| Validator | ตัวตรวจตารางอิสระจาก solver ผูกกับเลขข้อคะแนน |
| contract | สัญญากลาง ดูแลใน repo `ai-contract` (ไม่ได้อยู่ใน repo นี้) · สำเนาอยู่ `frontend/contract/` |

## 5. กติการักษาความ sync (ทำทุกครั้งที่แก้เอกสาร)

1. แก้ที่ **ไฟล์เจ้าของ** ก่อน แล้วค่อยแก้ไฟล์ที่อ้างถึง
2. **อย่าคัดลอกตาราง** ข้ามไฟล์ — ใช้การอ้างอิง (`02 §2.3`) เพื่อไม่ให้ drift
3. ไม่เปลี่ยนเลข `§` ของหัวข้อที่มีไฟล์อื่นอ้างถึง (เพิ่มหัวข้อใหม่ต่อท้าย)
4. เพิ่ม/ลบรหัส (FR/W/Q…) ต้องอัปเดตตาราง FR→W ที่ `06 §6`
5. เปลี่ยน contract (ฟิลด์/สถานะ/รหัสข้อผิดพลาด) = แก้ `02 §2` + เปิด PR `ai-contract` + อัปเดต 03/04/05 ที่อ้างถึงในวันเดียวกัน
6. ตรวจก่อนจบ: อ้างอิง `§` ทุกตัวชี้หัวข้อที่มีจริง · ไม่มีไฟล์ที่อ้างแต่ไม่อยู่ใน `docs/`

## 7. การตัดสินใจที่ตกลงแล้ว (ในแชต)
- เว็บ 3 หน้า: นำเข้า / ประมวลผล / ผลลัพธ์ · หน้าที่ตาม `03`
- React + Vite + TypeScript
- ทำแผน/ออกแบบก่อน ยังไม่เขียนโค้ดจริง (ตัวอย่างสั้นๆ ในเอกสารได้)
- แก้เฉพาะภายใน `docs/` ในรอบการเรียบเรียงนี้

## 8. สถานะและสิ่งที่ยังไม่ได้ตรวจ
- ทั้งชุดเป็น **ร่างออกแบบ** ยังไม่ผ่านการตรวจโดยกรรมการ/เพื่อน
- การประเมินความเป็นไปได้ใน 01 §5 เป็นการคิดด้วยมือ · ข้อเสนอโครงตัวแปรของ solver (04 §4.1) ยังไม่พิสูจน์ · spike S1–S5 ยังไม่ทำ
- `ai-contract` (repo แยก) ยังเป็น placeholder — แผนนี้ต้องการ contract v0.2 + fixtures F1–F4 ก่อน W3a (06 §3)
- ข้อความ PDF ของโจทย์ได้จากการดึง text อัตโนมัติ — ตัวเลขทุกจุดควรเทียบกับต้นฉบับอีกครั้ง
